# colorcpp v1.0.1 Release Process

This checklist is the concrete path to publish `colorcpp v1.0.1` on GitHub.

## Pre-release Checks

- [ ] Confirm the working tree is clean except for intentional release-doc changes.
- [ ] Verify the current version in [CMakeLists.txt](../../CMakeLists.txt) is `1.0.1`.
- [ ] Make sure [CHANGELOG.md](../../CHANGELOG.md) and [docs/release-notes/v1.0.1.md](../release-notes/v1.0.1.md) describe the release accurately.
- [ ] Run the full test suite:

```bash
cmake -G Ninja -B build -S . \
  -DCMAKE_BUILD_TYPE=Release \
  -DCOLORCPP_BUILD_TESTS=ON \
  -DCOLORCPP_BUILD_EXAMPLES=ON
cmake --build build --parallel
ctest --test-dir build --output-on-failure
```

- [ ] (Optional) Run SIMD tests:

```bash
cmake -G Ninja -B build-simd -S . \
  -DCMAKE_BUILD_TYPE=Release \
  -DCOLORCPP_BUILD_TESTS=ON \
  -DCOLORCPP_BUILD_EXAMPLES=ON \
  -DCOLORCPP_ENABLE_SIMD=ON
cmake --build build-simd --parallel
ctest --test-dir build-simd --output-on-failure
```

- [ ] (Optional) Run benchmarks to confirm no performance regression:

```bash
cmake -G Ninja -B build-bench -S . \
  -DCMAKE_BUILD_TYPE=Release \
  -DCOLORCPP_BUILD_BENCHMARKS=ON \
  -DCOLORCPP_ENABLE_SIMD=ON
cmake --build build-bench --parallel
cmake --build build-bench --target run_all_benchmarks
```

## Tagging

- [ ] Create the release tag locally.

```bash
git tag -a v1.0.1 -m "colorcpp v1.0.1"
```

- [ ] Push the tag to GitHub.

```bash
git push origin v1.0.1
```

## GitHub Release

- [ ] Open the GitHub Releases page for `merlotqi/colorcpp`.
- [ ] Create a new release from tag `v1.0.1`.
- [ ] Set the release title to `colorcpp v1.0.1`.
- [ ] Paste the contents of [docs/release-notes/v1.0.1.md](../release-notes/v1.0.1.md) into the release body.
- [ ] Attach the source archive generated by GitHub Releases.
- [ ] Publish the release.

## Post-release

- [ ] Verify the release page shows the correct tag, body, and source archive.
- [ ] Verify the Docker CD workflow triggered and published the `v1.0.1` image to GHCR.
- [ ] Verify the CI badge in README.md still shows green.
- [ ] Announce the release through project channels.
- [ ] If a follow-up version bump is planned, create the next changelog entry before starting new feature work.

## Docker CD verification

The `docker-publish.yml` workflow triggers automatically on `v*` tags:

- [ ] Check that the [Packages](https://github.com/merlotqi/colorcpp/pkgs/container/colorcpp) page lists the new `v1.0.1` image.
- [ ] Pull and smoke-test:

```bash
docker pull ghcr.io/merlotqi/colorcpp:v1.0.1
docker run --rm ghcr.io/merlotqi/colorcpp:v1.0.1
```
