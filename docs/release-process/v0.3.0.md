# colorcpp v0.3.0 Release Process

This checklist is the concrete path to publish `colorcpp v0.3.0` on GitHub.

## Pre-release Checks

- [ ] Confirm the working tree is clean except for intentional release-doc changes.
- [ ] Verify the current version in [CMakeLists.txt](CMakeLists.txt) is `0.3.0`.
- [ ] Make sure [CHANGELOG.md](CHANGELOG.md) and [docs/release-notes/v0.3.0.md](docs/release-notes/v0.3.0.md) describe the release accurately.
- [ ] Run the relevant verification commands:

```bash
ctest --test-dir build --output-on-failure
cmake --build build --target ansi_example io_example
```

## Tagging

- [ ] Create the release tag locally.

```bash
git tag -a v0.3.0 -m "colorcpp v0.3.0"
```

- [ ] Push the tag to GitHub.

```bash
git push origin v0.3.0
```

## GitHub Release

- [ ] Open the GitHub Releases page for `merlotqi/colorcpp`.
- [ ] Create a new release from tag `v0.3.0`.
- [ ] Set the release title to `colorcpp v0.3.0`.
- [ ] Paste the contents of [docs/release-notes/v0.3.0.md](docs/release-notes/v0.3.0.md) into the release body.
- [ ] Attach the source archive generated by GitHub Releases.
- [ ] Publish the release.

## Post-release

- [ ] Verify the release page shows the correct tag, body, and source archive.
- [ ] If Debian packaging is part of the release announcement, point users to the `libcolorcpp-dev` package workflow documented in the repo.
- [ ] If a follow-up version bump is planned, create the next changelog entry before starting new feature work.
